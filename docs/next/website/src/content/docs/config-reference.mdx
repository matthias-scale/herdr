Browse every canonical key Herdr reads from `config.toml` in a flat, filterable list. For setup guidance
and the reasoning behind these options, see [Configuration](/docs/configuration/).

Print the full commented default config at any time:

```bash
herdr --default-config
```

Custom command bindings (`[[keys.command]]`) are user-defined tables and are not
listed per key here; see
[Custom command keybindings](/docs/configuration/#custom-command-keybindings).

`remote.fleet.self_name` identifies this server in `host::agent` references and
defaults to the local fleet host name, then the system hostname.

Set `planning_lock.authority` on a follower to the SSH target of the server that
owns planning-lock state. See [Planning lock](/docs/planning-lock/#shared-state).

`[[launch_profiles]]` is a user-defined array of tables and is therefore not
listed per key here. Each launch profile names one way to start an agent from
the Home composer, including its agent type, command, environment, and optional
quota source.

Home and Spawn share a provider/account/model picker. Open the provider or model
field, use Tab to move between accounts and models, type to search the installed
model catalog, and use Enter to select or Escape to close. The narrow layout
stacks the account list above models. The popup opens next to the Agent or Model
field that opened it, flips above when space below is limited, and stays inside
the viewport. Arrows and the mouse wheel navigate each list using the same
geometry as the rendered rows and click targets. Home and the popup use the
active light or dark palette.

Popup rows and selected Home/Spawn provider chips reuse sidebar provider icons
(plain provider tags without Nerd Fonts),
short account identities and compact remaining percentages. `?` means unknown,
`◷` marks stale last-known usage, `⊘` marks an unavailable binding or source,
`!` marks expired authentication and `■0%` marks exhaustion. The selected-account
details retain the full reason, windows, reset and freshness information.
Duplicate account labels include their stable ID, and custom launch lanes keep
their lane label.

Model labels omit repeated provider names while search still matches the full ID
and previous display name. Claude fallback choices include Fable 5.1, Opus 5.5,
Sonnet 5.5 and Haiku 5.5 using their exact IDs from the
[official model reference](https://platform.claude.com/docs/en/models/overview).
Historical pinned IDs retain their own version labels and are never silently
upgraded. Account-specific live catalogs continue to take precedence; the fallback
list is not proof of subscription availability. Codex catalogs still come from
native account-specific discovery, with short labels for the known Astra, Luna,
Sol and Terra IDs; missing catalogs do not invent those models.

The `inherited` row preserves the launch profile and ambient environment. An
explicit Codex account uses a discovered native profile's per-process `CODEX_HOME`.
Claude capture archives remain visible for quota information, but are never used
as native config directories. On Unix, a known Claude subscription account with
metadata and a unique verified token-name mapping uses a private Herdr child
launcher. Only that child retrieves the selected name through `secret-get`, sets
`CLAUDE_CODE_OAUTH_TOKEN`, and executes the original native model/effort arguments.
Token values never enter the picker, saved drafts or launch request. The picker
marks subscription authentication as checked at launch; metadata alone does not
prove token availability. Retrieval failure refuses before Claude starts and
never falls back to the inherited account. Native Claude Code 2.1.299 or newer
and the canonical local `secret-get` helper are required. Windows explicit
Claude token launches remain unavailable until a native helper contract exists.
Labels and cached default rows do not establish launch bindings. Unverified
accounts, colliding token names, authentication/provider/config overrides,
wrapper commands and remote account bindings refuse an explicit selection.
Inherited Claude launches remain unchanged.
Quota windows belong to the selected account and show remaining usage, reset
and freshness; missing data stays unknown, stale data is last-known, and login
or helper failures remain visible. No global account switch is performed.

`[[projects]]` is likewise a user-defined array of tables. Each project groups
checkouts for the Home composer's project and repo selectors through `roots`
and `repos`; see [Projects](/docs/configuration/#projects).

Fleet polling uses `remote.fleet.refresh_interval_ms` for its background refresh
period and `remote.fleet.timeout_ms` as the deadline for each configured host.
Set `remote.fleet.hosts[].session` to open that host's named Herdr session.
Set `remote.fleet.symphony_host` to a configured host name when Temporal runs on
another machine. When unset, Symphony keeps polling localhost.
The Inbox sidebar section reads `agent-inbox healthcheck --json` from
`remote.fleet.inbox_host`; when unset, it uses `remote.fleet.aloop_host`.

Settled panes stay live and editable for `session.settled_read_only_after_minutes`
(15 minutes by default), then become read-only transcripts. Set it to `0` to
lock panes immediately. By default, `session.settle_stops_agent` stops an agent
only when Herdr has a supported native resume plan. Unsettling a pane during its
grace period continues the live session; after it locks, Enter resumes the stored
agent session. Set `session.settle_stops_agent` to `false` to keep settled agents
running after the grace period too.
